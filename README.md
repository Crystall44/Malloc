# Собственный аллокатор памяти (malloc)

Реализация собственного менеджера динамической памяти с алгоритмом Best Fit, защитой от повреждений и выравниванием блоков.

# Что такое malloc и зачем он нужен

malloc - это фундаментальная функция стандартной библиотеки C, которая выделяет память во время выполнения программы.  
Каждый раз, когда программа создаёт массив, строку или структуру через указатель — под капотом работает malloc.

Аллокатор управляет всей доступной памятью процесса (кучей), отслеживает занятые и свободные блоки, сливает освобождённые блоки для борьбы с фрагментацией.

# Особенности реализации

## Алгоритм поиска Best Fit

Best Fit ищет наименьший блок, достаточный для размещения данных. Это уменьшает внешнюю фрагментацию - не остаётся больших «огрызков» от крупных блоков, которые раздавали мелким запросам.

## Слияние соседних свободных блоков

При освобождении памяти блок не просто возвращается в список свободных - он пытается объединиться с физическими соседями слева и справа.  
Это ключевой механизм борьбы с фрагментацией: если освободить три соседних блока по 100 байт, они сольются в один блок на 300 байт.

## Защита от повреждений (Magic Cookie)

Каждый блок памяти содержит сигнатуру 0xDEADBEEF в заголовке. При выделении и освобождении эта сигнатура проверяется.  
Если память была повреждена (выход за границы массива, запись в освобождённый блок) - аллокатор немедленно сообщит об ошибке, а не продолжит работу с мусором.

## Выравнивание по 16 байт

Все возвращаемые указатели выровнены по границе 16 байт.  
Это требование современных процессоров: многие SIMD-инструкции (SSE) требуют выровненных данных, и невыровненный доступ может привести к падению программы или снижению производительности в десятки раз.

# Основные операции
  
my_malloc(size) - Выделяет блок памяти заданного размера  
my_free(ptr) - Освобождает ранее выделенный блок (с автоматическим слиянием)  
my_calloc(nmemb, size) - Выделяет и обнуляет память под массив  
my_realloc(ptr, size) - Изменяет размер ранее выделенного блока

# Внутреннее устройство

## Структура блока
Каждый блок памяти (и свободный, и занятый) имеет заголовок BlockHeader:  
size - размер всего блока (заголовок + данные)  
free - флаг: 1 = свободен, 0 = занят  
next, prev - указатели для двусвязного списка свободных блоков  
cookie - сигнатура 0xDEADBEEF для проверки целостности  

Свободные блоки объединены в двусвязный список для быстрого поиска и удаления.

## Поиск блока (Best Fit)
Алгоритм проходит по всему списку свободных блоков и запоминает наименьший подходящий. При точном совпадении размера поиск прекращается досрочно.

## Разделение блока
Если найденный блок значительно больше запрошенного, он разделяется на два: выделяемая часть и остаток.  
Остаток возвращается в список свободных. Это предотвращает расточительство памяти.

## Слияние блоков
При освобождении проверяются физические соседи (слева и справа). Если сосед свободен - блоки объединяются в один. Это ключевой механизм борьбы с фрагментацией.

## Инициализация кучи
При первом вызове my_malloc через Windows API (HeapCreate + HeapAlloc) выделяется 50 MB непрерывной памяти.  
Внутри этого региона аллокатор управляет блоками самостоятельно, без дополнительных системных вызовов.
